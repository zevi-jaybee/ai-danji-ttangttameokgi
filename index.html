01 · 설치와 연결

설치와 연결

QGIS 안의 플러그인과 Claude 쪽의 서버, 두 부분을 같은 버전으로 설치합니다. 기준은 플러그인 관리자의 0.14.1(2026-09-17 공개)입니다. 0.13의 패널 [Start Server]는 툴바 아이콘으로 바뀌었습니다.

01

uv 설치

PowerShell을 열고 한 줄을 붙여 넣습니다. 프롬프트가 PS로 시작해야 PowerShell입니다. 설치가 끝나면 창을 닫고 새로 연 뒤 uv --version이 번호를 찍는지 봅니다. 창을 새로 열지 않으면 다음 단계에서 uvx를 못 찾습니다.

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
02

QGIS 플러그인 QGIS MCP 0.14.1

플러그인 › 플러그인 관리 및 설치 › 검색창에 QGIS MCP. 저자 Nicolas Karasiak, 0.14.1을 설치합니다. 환영 창은 닫습니다. 플러그인 툴바에 아이콘이 하나 생깁니다.

아이콘을 누르면 서버가 켜지고 아이콘이 초록색이 됩니다. Claude가 붙으면 빨간 숫자가 달리고, 그 숫자가 연결된 클라이언트 수입니다. 아이콘 옆 ▾를 눌러 Auto-start on startup을 체크해 둡니다. 포트는 9876 그대로 둡니다.

03

Claude Code 등록

새 PowerShell 창에서 아래 한 줄을 실행합니다. 줄바꿈 없이 한 줄입니다. 주소 끝의 v0.14.1이 플러그인 관리자에서 설치한 번호와 같아야 합니다. -s user를 빼면 그 폴더에서만 등록되어 다른 폴더에서 claude를 켜면 QGIS가 안 보입니다.

claude mcp add -s user qgis -- uvx --from https://github.com/nkarasiak/qgis-mcp/archive/refs/tags/v0.14.1.zip qgis-mcp-server

▾ 메뉴의 Configure… 창도 명령을 만들어 주지만 그 명령은 최신판(main.zip)을 가리키고 -s user가 없습니다. 위 한 줄을 씁니다. Configure 창은 버전 불일치 확인용입니다. 불일치는 주황 글씨로 표시됩니다.

04

연결 확인

QGIS를 켜고 아이콘이 초록색인 상태에서 데이터 폴더로 이동해 Claude Code를 시작합니다. 처음 한 번은 서버 패키지 40개쯤을 내려받느라 몇 분 걸립니다.

cd "C:\studio3\내이름\buyeo_3km"
claude

세션이 열리면 두 문장

QGIS에 연결됐는지 ping 해 줘
diagnose 해서 플러그인 버전과 서버 버전이 같은지 봐 줘

pong이 오고 plugin 0.14.1 / server 0.14.1처럼 두 숫자가 같으면 연결된 것입니다. mismatch가 나오면 03의 주소 끝 번호를 플러그인 번호에 맞추고, PowerShell에서 uv cache clean qgis-mcp를 실행한 뒤 Claude Code를 다시 시작합니다.

처음 몇 번은 Claude Code가 도구 사용 허가를 묻습니다. ping·diagnose·get_으로 시작하는 읽기 도구는 "항상 허용"으로 두어도 됩니다. execute_code·remove_layer·delete_features는 매번 확인합니다. QGIS 안에서 파이썬이 실행되는 도구입니다.

버전이 다르면. 기본 도구는 동작하지만 최근에 추가된 도구는 "알 수 없는 명령"으로 실패합니다. 플러그인을 올리면 서버 태그도 같이 올립니다.

I

작업 파일 만들기

배포 gpkg는 손대지 않습니다. 같은 폴더에 계획용 gpkg를 따로 만들고 다섯 레이어를 빈 채로 넣습니다. 좌표계는 배포본과 같은 EPSG:5179, 면적은 나중에 5186에서 잽니다.

QGIS에서 프로젝트 폴더에 plan_v1.gpkg를 만들고 EPSG:5179로 다섯 레이어를 빈 채로 넣어 줘. 01_도로중심선(선: 위계·노선 문자, 폭원 실수), 02_도로면(면: 용도, 면적), 03_가구(면: 가구·용도 문자, 면적·장변·단변 실수, 획지수 정수), 04_획지(면: 번호·획지유형·가구 문자, 면적·전면폭·깊이·세장비·접도연장 실수, 맹지 불리언), 05_용지(면: 용지, 면적). 그룹 'A1 계획'으로 올려 줘

도구 execute_code(QgsVectorFileWriter) → create_layer_group · add_vector_layer

확인: 레이어 패널에 그룹과 다섯 레이어가 보이고, 각 레이어의 좌표계가 EPSG:5179인지 "다섯 레이어의 좌표계와 필드를 표로 보여 줘"로 되묻습니다.

왜 gpkg 하나에 다섯 레이어인가. SHP는 필드명이 10바이트에서 잘리고 한글이 깨집니다. gpkg는 한 파일에 여러 레이어를 담고 UTF-8이라 편입면적_㎡ 같은 이름도 그대로 갑니다. 판을 바꿀 때는 파일째 복사해 plan_v2.gpkg로 씁니다.
II

도로중심선

도로는 중심선 하나에 폭원 값을 붙여 그립니다. 도로면은 다음 단계에서 폭원으로 만듭니다. 이 단계에서 정하는 것은 위계와 폭원입니다.

방법은 둘입니다. QGIS에서 마우스로 긋거나(편집 모드 → 선 객체 추가, 스냅 켜기), 좌표나 관계를 문장으로 줍니다. 데모는 후자입니다. A1은 서쪽 변이 대로1류, 북쪽 변이 중로2류, 동쪽 변이 소로2류에 접합니다. 시험 판은 진입을 북쪽에서 받고 서쪽은 차량 출입을 막았습니다.

01_도로중심선에 선 n개를 넣어 줘. R1 어귀길 n m: 북쪽 경계 x=…에서 남쪽 A2 경계까지 남북. R2 안길 n m: y=…에서 서쪽 경계부터 동쪽 경계까지 동서. R3·R4 샛길 n m: y=…, … 동서. R5 샛길 n m: x=…, R3에서 R4까지. R6·R7 골목 n m: x=…, y=…. 다 넣은 뒤 01_부지경계 A1으로 잘라내고, 노선별 연장을 EPSG:5186에서 재서 표로 보여 줘

도구 add_features(WKT) → execute_code(부지로 자르기, 연장)

확인: 노선 n개, 연장 합 n m, 부지 면적으로 나눈 도로밀도 n m/ha. 비교값은 황룡 한옥마을 실측 도로밀도 227 m/ha입니다.

III

도로면과 완충녹지

중심선을 폭원의 절반으로 양쪽에 버퍼하면 도로면이 됩니다. 끝은 평탄(flat)으로 잘라야 교차부가 정리됩니다. 대로1류에 면한 서쪽 변은 안쪽 n m를 완충녹지로 두고, 도로면에서 녹지를 뺍니다.

01_도로중심선을 각 노선의 폭원/2로 평탄 끝(flat cap) 버퍼해서 하나로 합치고 A1으로 잘라 02_도로면에 넣어 줘. 04_도시계획도로의 대로1류에 면한 A1 변에서 안쪽 n m를 완충녹지로 만들어 05_용지에 '완충녹지'로 넣고, 도로면에서는 그 녹지를 빼 줘. 둘 다 면적은 EPSG:5186으로. 폭원×연장 합과 도로면 실측 면적도 같이 보여 줘

도구 execute_code(buffer · unaryUnion · difference) — 또는 execute_processing native:buffer + native:dissolve + native:clip

확인: 도로면 n ㎡(n %), 완충녹지 n ㎡(n %). 폭원×연장의 합과 도로면 실측의 차이는 교차부 중복과 녹지에 잘린 부분입니다. 도로조서에는 노선별 값을 남기고 합계란에는 실측값을 적습니다.

도로율 n %는 상한입니다. 폭이 넓은 도로를 늘리거나 격자를 좁히면 도로율이 오릅니다. 도로와 녹지는 묶지 않고 각각 상한·하한으로 적습니다.
메뉴로 하면. 벡터 › 지오프로세싱 도구 › 버퍼(거리 폭원/2, 끝 유형 평탄) → 디졸브 → 잘라내기(A1).
IV

가구

부지에서 도로면과 녹지를 뺀 조각이 가구입니다. 조각마다 번호를 붙이고 면적·장변·단변을 잽니다. n ㎡ 미만 조각은 버리고 개수와 면적을 기록합니다.

A1에서 02_도로면과 완충녹지를 빼서 남는 조각을 03_가구에 넣어 줘. 북에서 남, 서에서 동 순으로 B01부터 번호를 붙이고, 용도는 '주거'로 두고, 면적(5186)·장변·단변(최소외접사각형)을 채워 줘. n ㎡ 미만 조각은 버리고 몇 개를 버렸는지 알려 줘. 가구 면적 합 + 도로면 + 녹지가 부지 면적(분모)과 얼마나 다른지도

도구 execute_code(difference → 단일 폴리곤 분리 → orientedMinimumBoundingBox)

확인: 가구 n개, 합계와 분모의 차이 n ㎡(버린 조각 + 반올림). 가구 규모 n~n ㎡. 기준보다 큰 가구는 골목을 추가할 후보입니다.

획지

Claude가 나눈 결과는 초안입니다. 규칙은 셋입니다. 가구에서 도로에 닿는 변 중 하나를 전면으로 잡는다. 전면을 따라 목표 전면폭(n m)으로 자른다. 반대편도 도로에 닿고 깊이가 n m 이상이면 가운데를 갈라 두 줄로 만든다.

03_가구 중 용도가 주거인 가구를 04_획지로 나눠 줘. 전면은 도로면(02_도로면과 04_도시계획도로)에 닿는 변 중 획지 깊이가 n m에 가장 가까워지는 변으로 잡고, 전면폭 n m 목표로 균등 분할, 반대편도 도로에 닿고 깊이 n m 이상이면 두 줄로. 번호는 B01-01 식으로. 면적(5186)·전면폭(도로에 닿는 가장 긴 직선 변)·깊이(면적/전면폭)·세장비·접도연장(도로에 닿는 길이 전부)·맹지(접도 n m 미만)를 채우고, 획지유형은 n 미만 '기준 미달', n 이상 '기준 초과', 그 사이는 소(n 미만)·중(n 미만)·대로. 선을 폴리곤화하기 전에 반드시 노드 처리(unaryUnion)를 하고, n ㎡ 미만 조각은 버리되 알려 줘. 가구마다 획지수도 채워 줘

도구 execute_code(unaryUnion → polygonize) — 유형별 집계는 execute_sql

확인: 획지 n개. 유형별 수와 맹지 수를 표로 봅니다. 사선 경계(대로1류 변)에서 생긴 조각은 기준 미달·맹지로, 깊은 가구가 한 줄로 잘린 자리는 기준 초과로 나타납니다. 둘 다 계산 오류가 아니라 계획에서 고칠 항목입니다.

초안에서 고칠 것. 사선 경계의 조각은 이웃 획지와 합치거나 녹지로 넘깁니다. 깊은 가구는 골목을 하나 더 넣어 두 줄로 만듭니다. 모퉁이 획지는 긴 쪽이 전면으로 잡히므로 조서에서 전면폭을 확인합니다. 이 세 가지는 손으로 고칩니다.

용지와 제원표

가구에 용도를 지정하면 제원표가 됩니다(예: B05 공원, B08 상업, B09 공용·커뮤니티, 나머지 주거). 주거가 아닌 가구의 획지는 지웁니다.

03_가구에서 B05는 공원, B08은 상업, B09는 공용·커뮤니티로 바꾸고 그 가구의 획지는 04_획지에서 지워 줘. 그다음 05_용지를 다시 만들어 줘: 가구 용도별 합, 도로면, 완충녹지. 양식 1 형식(용지 × ㎡ · %)으로 표를 만들고 분모는 부지 면적, 합계와 분모의 차이는 '미배분' 행으로. 주거 획지 수를 호수로 보고 총밀도(분모 전체 부지)와 순밀도(분모 주거용지)를 호/ha로 내 줘

도구 update_features · delete_features · execute_code · evaluate_expression

확인: 오른쪽 표가 나와야 합니다. 용지 비율과 총밀도를 기준값과 대조해 판정을 적습니다. 기준을 넘으면 획지 확대, 주거 가구의 공원 전환 등으로 조정합니다.

04 · 조서 네 가지

조서 네 가지

토지이용제원표·가구조서·획지조서·도로조서. 면적 열은 자동으로 나오고 전면폭·깊이·세장비·접도연장은 그린 도형에서 계산됩니다. 세 표의 합계는 분모(부지 면적)와 같아야 하며, 각 표에 검산란을 둡니다.

plan_v1.gpkg에서 조서 네 개를 CSV로 만들어 줘. 도로조서(노선·위계·폭원·연장·폭원×연장, 합계란에 도로면 실측과 차이), 가구조서(가구·용도·면적·장변·단변·획지수), 획지조서(번호·가구·유형·면적·전면폭·깊이·세장비·접도연장·맹지), 토지이용제원표(양식 1). 전부 EPSG:5186, UTF-8 BOM으로 프로젝트 폴더의 조서 폴더에 저장하고, 세 표의 합계가 서로 맞는지 알려 줘
도로조서

노선별 값과 실측을 나란히

노선별 폭원×연장의 합과 도로면 실측을 나란히 적고, 차이(교차부 중복·녹지 절단)를 밝힙니다. 합계란에는 실측을 씁니다.

가구조서

가구 · 용도 · 면적 · 장변 · 단변 · 획지수

가구 면적 합 + 도로 + 녹지 = 분모(부지 면적).

획지조서

전면폭 0, 세장비 3 이상 확인

전면폭 0은 맹지, 세장비가 3을 넘으면 폭이 좁고 깊은 획지입니다.

CSV 인코딩

Excel에서 한글이 깨지면 인코딩

QGIS 기본 내보내기(export_layer)는 CP949로 저장되어 한국어 Excel에서 바로 열립니다. 다른 프로그램에서 열 때는 "UTF-8 BOM으로"라고 다시 시킵니다.

05 · 출력과 CAD 왕복

출력과 CAD

레이아웃은 기본이 A4 가로(297×210)이므로 A3를 따로 지정합니다. 범례는 프로젝트의 레이어를 전부 담으므로 지도에 없는 레이어는 미리 끕니다.

'A1 계획 A3' 인쇄 레이아웃을 만들고 용지를 A3 가로(420×297mm)로. 지도는 (10,22)에 300×265mm, 축척 1:1,500, 제목 라벨은 위에, 범례는 (320,22)에 90×200mm로 도로중심선·획지·가구·용지만, 축척막대는 (318,262)에 40 m 3칸. PNG 110dpi와 PDF로 프로젝트 폴더에 내보내 줘

도구 create_layout → execute_code(용지 크기) → add_layout_map · add_layout_label · add_layout_legend · add_layout_scalebar → export_layout. 내보내기는 export_layout 도구로 합니다. 화면이 그려지는 중에 코드로 내보내면 QGIS가 종료됩니다.

DXF 로 내보내기

export_layer는 DXF에 실패

DXF는 임의 필드를 받지 않습니다. "QgsDxfExport로 다섯 레이어를 5179 DXF로 내보내 줘. 도로중심선은 위계, 용지는 용지 값을 레이어명으로"라고 시키면 레이어별 닫힌 폴리라인으로 나옵니다.

AutoCAD에서 안 열리면

ezdxf로 한 번 다시 저장

QGIS가 쓴 DXF는 코드페이지가 비어 있어 AutoCAD가 "Invalid or incomplete DXF input"으로 거부하거나 한글 레이어명이 깨질 수 있습니다. "ezdxf로 읽어 인코딩 cp949, $DWGCODEPAGE ANSI_949로 다시 저장해 줘". 이렇게 만든 파일은 AutoCAD 2026에서 AUDIT 오류 0으로 확인했습니다.

프로젝트 저장

배포 qgz는 두고 다른 이름으로

"프로젝트를 buyeo_3km_plan_v1.qgz로 저장해 줘". 경로는 상대경로로 저장되므로 gpkg와 같은 폴더에 있어야 합니다. 폴더째 옮기는 것은 괜찮습니다.
